# Проверка реализации

Дата: 2026-09-28.

## Среда

- Apache NiFi 2.6.0, официальный образ `docker.io/apache/nifi:2.6.0`, ARM64.
- PostgreSQL 17.11, существующая база `supply_lab` в `lr1-postgres`.
- PostgreSQL JDBC 42.7.7.
- Python 3.14.6 на хосте; Python 3.11.2 внутри NiFi.

Таблицы `public` ЛР1 не изменялись; установлена только схема `lr8`.
Тестовые события и квитанции оставлены в `lr8.delivery_events` и `runtime`.

## Выполненные проверки

| Проверка | Результат |
| --- | --- |
| `python3 -m unittest discover -s tests -v` | 15 тестов: генерация, атомарная публикация, ошибки, контракт, расписание и структура потока |
| `tests/test_database.sql` через psql | Ограничения, запрет дублей, откат частичной вставки; тест завершён ROLLBACK |
| `scripts/import_flow.py` | JSON импортирован; sensitive-параметр установлен; JDBC Verify успешен; все процессоры валидны и запущены |
| `python3 tests/integration.py` | 16 сценариев; корректные файлы из 2 и 20 записей, все ошибки входа, повторная доставка, конфликт во второй записи |
| `python3 tests/recovery.py` | Файл удержан при остановке PostgreSQL, очередь сохранена после перезапуска NiFi, файл загружен после восстановления БД |
| Реальный `--watch --interval 10 --count 2` | Два разных файла созданы и загружены, для обоих проверены квитанции и число строк в БД |
| Стиль Python | `ruff check --isolated --select E4,E7,E9,F,I src scripts tests` |

Интервал 300 секунд проверен модульным тестом с управляемыми часами; реальная
демонстрация выполнена с разрешённым RFC ускорением до 10 секунд.

Интеграционный тест проверяет побайтовое совпадение архива и rejected-файлов
с оригиналами, отсутствие частичных вставок и отсутствие значений записи в
тексте ошибки квитанции. Сбой диска при сохранении архива/квитанции отдельно
не воспроизводился: соответствующие failure-маршруты сохранены в очередях,
а отсутствие пути обратно к INSERT проверяется модульным тестом графа.

На завершение проверки все 33 процессора имеют статус VALID/RUNNING,
очереди пусты. `tests/verify_database.sql` подтвердил 20 строк для последнего
файла из 20 событий; новые журналы NiFi не содержат значений SKU записей.

## Уточнения, подтверждённые запуском

- API-имена свойств NiFi 2.6.0 отличаются от подписей в UI; в JSON сохранены
  проверенные на установленном сервере имена, например `put-db-record-table-name`.
- Ошибка подключения к PostgreSQL может выходить через `PutDatabaseRecord.failure`.
  Поэтому отдельная классификация оставляет такие файлы в цикле RetryFlowFile.
- JDBC без `logServerErrorDetail=false` может включать значения параметров INSERT
  в сообщения об ошибке. В стандартном URL эта возможность отключена.
- Гарантии доставки — повторная доставка с защитой уникальными ключами;
  атомарной общей транзакции NiFi + PostgreSQL + файловая система нет.
