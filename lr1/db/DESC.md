# Описание базы данных `supply_lab`

База данных моделирует поставки товаров от поставщиков на склады. Сущности
`suppliers`, `products` и `warehouses` являются родительскими. Таблица
`deliveries` реализует тернарное отношение многие-ко-многим между этими
сущностями и хранит характеристики конкретной поставки. Таблица
`warehouse_sections` описывает иерархию складских секций с помощью рекурсивной
связи.

Кодировка базы данных — UTF-8. Все даты и время записываются без часового
пояса. Денежные значения хранятся в типе `numeric`, чтобы избежать погрешности
чисел с плавающей точкой.

## Таблица `suppliers`

Содержит сведения о поставщиках. Суррогатный ключ генерируется PostgreSQL с
помощью `GENERATED BY DEFAULT AS IDENTITY`.


| Поле          | Тип             | NULL | Описание                                      |
| ------------- | --------------- | ---- | --------------------------------------------- |
| `supplier_id` | `bigint`        | Нет  | Суррогатный идентификатор поставщика.         |
| `name`        | `varchar(120)`  | Нет  | Полное наименование поставщика.               |
| `tax_id`      | `varchar(12)`   | Нет  | Налоговый идентификатор поставщика.           |
| `country`     | `varchar(80)`   | Нет  | Страна регистрации поставщика.                |
| `city`        | `varchar(80)`   | Нет  | Город регистрации поставщика.                 |
| `email`       | `varchar(160)`  | Нет  | Контактный адрес электронной почты.           |
| `phone`       | `varchar(24)`   | Нет  | Контактный номер телефона.                    |
| `rating`      | `numeric(3, 2)` | Нет  | Рейтинг поставщика от 1,00 до 5,00.           |
| `is_active`   | `boolean`       | Нет  | Признак возможности принимать новые поставки. |
| `created_at`  | `date`          | Нет  | Дата добавления поставщика в систему.         |




### Ограничения `suppliers`

- `suppliers_pk` — первичный ключ по `supplier_id`.
- `suppliers_tax_id_uq` — уникальность `tax_id`.
- `suppliers_email_uq` — уникальность `email`.
- `suppliers_rating_ck` — значение `rating` находится в диапазоне от 1,00 до 5,00 включительно.
- Все поля таблицы обязательны и имеют ограничение `NOT NULL`.



## Таблица `products`

Содержит товарный справочник. `product_id` является автоматически генерируемым
суррогатным ключом.


| Поле            | Тип              | NULL | Описание                                                 |
| --------------- | ---------------- | ---- | -------------------------------------------------------- |
| `product_id`    | `bigint`         | Нет  | Суррогатный идентификатор товара.                        |
| `sku`           | `varchar(20)`    | Нет  | Уникальный складской код товара.                         |
| `name`          | `varchar(160)`   | Нет  | Наименование товара.                                     |
| `category`      | `varchar(80)`    | Нет  | Категория товара.                                        |
| `unit`          | `varchar(12)`    | Нет  | Единица измерения: штуки, килограммы, литры или коробки. |
| `unit_price`    | `numeric(12, 2)` | Нет  | Текущая справочная цена единицы товара.                  |
| `weight_kg`     | `numeric(10, 3)` | Нет  | Масса единицы товара в килограммах.                      |
| `is_perishable` | `boolean`        | Нет  | Признак скоропортящегося товара.                         |
| `created_at`    | `date`           | Нет  | Дата добавления товара в справочник.                     |




### Ограничения `products`

- `products_pk` — первичный ключ по `product_id`.
- `products_sku_uq` — уникальность `sku`.
- `products_unit_price_ck` — значение `unit_price` строго больше нуля.
- `products_weight_ck` — значение `weight_kg` строго больше нуля.
- Все поля таблицы обязательны и имеют ограничение `NOT NULL`.



## Таблица `warehouses`

Содержит сведения о складах и их характеристиках. `warehouse_id` является
автоматически генерируемым суррогатным ключом.


| Поле                     | Тип              | NULL | Описание                                         |
| ------------------------ | ---------------- | ---- | ------------------------------------------------ |
| `warehouse_id`           | `bigint`         | Нет  | Суррогатный идентификатор склада.                |
| `code`                   | `varchar(16)`    | Нет  | Уникальный внутренний код склада.                |
| `name`                   | `varchar(160)`   | Нет  | Наименование склада.                             |
| `country`                | `varchar(80)`    | Нет  | Страна расположения склада.                      |
| `city`                   | `varchar(80)`    | Нет  | Город расположения склада.                       |
| `address`                | `varchar(240)`   | Нет  | Почтовый адрес склада.                           |
| `opened_on`              | `date`           | Нет  | Дата ввода склада в эксплуатацию.                |




### Ограничения `warehouses`

- `warehouses_pk` — первичный ключ по `warehouse_id`.
- `warehouses_code_uq` — уникальность `code`.
- Все поля таблицы обязательны и имеют ограничение `NOT NULL`.



## Таблица `warehouse_sections`

Содержит зоны и секции внутри складов. Поле `parent_section_id` ссылается на
другую строку этой же таблицы, формируя иерархию произвольной глубины. Корневая
секция имеет значение `NULL` в `parent_section_id`.


| Поле                | Тип              | NULL | Описание                                           |
| ------------------- | ---------------- | ---- | -------------------------------------------------- |
| `section_id`        | `bigint`         | Нет  | Автоматически генерируемый идентификатор секции.   |
| `warehouse_id`      | `bigint`         | Нет  | Идентификатор склада, которому принадлежит секция. |
| `parent_section_id` | `bigint`         | Да   | Идентификатор родительской секции того же склада.  |
| `code`              | `varchar(24)`    | Нет  | Внутренний код секции в пределах склада.           |
| `name`              | `varchar(160)`   | Нет  | Человекочитаемое наименование секции.              |
| `section_type`      | `varchar(20)`    | Нет  | Функциональный тип складской секции.               |
| `capacity_m3`       | `numeric(10, 2)` | Нет  | Вместимость секции в кубических метрах.            |
| `floor`             | `smallint`       | Нет  | Номер этажа, начиная с нуля.                       |
| `is_active`         | `boolean`        | Нет  | Признак доступности секции для складских операций. |


Допустимые значения `section_type`:

- `receiving` — приёмка товаров;
- `storage` — обычное хранение;
- `cold_storage` — хранение с температурным контролем;
- `packing` — упаковка и комплектация;
- `dispatch` — отгрузка товаров.



### Ограничения `warehouse_sections`

- `warehouse_sections_pk` — первичный ключ по `section_id`.
- `warehouse_sections_location_uq` — уникальность пары `warehouse_id` и `section_id`; используется составным рекурсивным внешним ключом.
- `warehouse_sections_code_uq` — код секции уникален в пределах одного склада.
- `warehouse_sections_warehouse_fk` — `warehouse_id` ссылается на `warehouses.warehouse_id`.
- `warehouse_sections_parent_fk` — пара `warehouse_id` и `parent_section_id` ссылается на пару `warehouse_id` и `section_id` этой же таблицы. Это не позволяет выбрать родителя с другого склада.
- `warehouse_sections_not_self_ck` — секция не может быть непосредственным родителем самой себя.
- `warehouse_sections_capacity_ck` — `capacity_m3` строго больше нуля.
- `warehouse_sections_floor_ck` — номер этажа неотрицательный.
- `warehouse_sections_type_ck` — `section_type` содержит только допустимое значение.
- Все поля, кроме `parent_section_id`, имеют ограничение `NOT NULL`.

Ограничения исключают прямую самоссылку, но циклы длиной более одной связи
должны предотвращаться прикладной логикой или отдельным триггером.

## Таблица `deliveries`

Содержит факты поставок и связывает поставщика, товар и склад. Одна запись
означает передачу партии определённого товара конкретным поставщиком на
конкретный склад. Помимо трёх внешних ключей таблица содержит собственные
атрибуты поставки.


| Поле             | Тип                           | NULL | Описание                                                          |
| ---------------- | ----------------------------- | ---- | ----------------------------------------------------------------- |
| `delivery_id`    | `bigint`                      | Нет  | Автоматически генерируемый идентификатор поставки.                |
| `supplier_id`    | `bigint`                      | Нет  | Идентификатор поставщика из `suppliers`.                          |
| `product_id`     | `bigint`                      | Нет  | Идентификатор поставленного товара из `products`.                 |
| `warehouse_id`   | `bigint`                      | Нет  | Идентификатор склада назначения из `warehouses`.                  |
| `delivered_at`   | `timestamp without time zone` | Нет  | Дата и локальное время поступления партии.                        |
| `quantity`       | `integer`                     | Нет  | Количество единиц товара в партии.                                |
| `unit_cost`      | `numeric(12, 2)`              | Нет  | Фактическая закупочная стоимость единицы товара.                  |
| `batch_number`   | `varchar(20)`                 | Нет  | Номер партии поставщика.                                          |
| `quality_status` | `varchar(16)`                 | Нет  | Результат приёмки партии.                                         |
| `expires_on`     | `date`                        | Да   | Срок годности; может отсутствовать для нескоропортящихся товаров. |


Допустимые значения `quality_status`:

- `accepted` — партия принята;
- `inspection` — партия находится на проверке;
- `rejected` — партия отклонена.



### Ограничения `deliveries`

- `deliveries_pk` — первичный ключ по `delivery_id`.
- `deliveries_business_key_uq` — комбинация `supplier_id`, `product_id`, `warehouse_id` и `batch_number` уникальна.
- `deliveries_supplier_fk` — внешний ключ `supplier_id` ссылается на `suppliers.supplier_id`.
- `deliveries_product_fk` — внешний ключ `product_id` ссылается на `products.product_id`.
- `deliveries_warehouse_fk` — внешний ключ `warehouse_id` ссылается на `warehouses.warehouse_id`.
- `deliveries_quantity_ck` — значение `quantity` строго больше нуля.
- `deliveries_unit_cost_ck` — значение `unit_cost` строго больше нуля.
- `deliveries_quality_status_ck` — значение `quality_status` входит в список `accepted`, `inspection`, `rejected`.
- Все поля, кроме `expires_on`, обязательны и имеют ограничение `NOT NULL`.

Удаление родительских записей при наличии связанных поставок запрещено
стандартным поведением внешних ключей `NO ACTION`. Каскадное удаление и
каскадное изменение идентификаторов не применяются.

## Индексы

PostgreSQL автоматически создаёт уникальные индексы для первичных ключей и
ограничений `UNIQUE`. Дополнительно определены следующие индексы:


| Индекс                          | Таблица и поля                                         | Назначение                                            |
| ------------------------------- | ------------------------------------------------------ | ----------------------------------------------------- |
| `deliveries_supplier_idx`       | `deliveries (supplier_id)`                             | Поиск поставок поставщика и соединение с `suppliers`. |
| `deliveries_product_idx`        | `deliveries (product_id)`                              | Поиск поставок товара и соединение с `products`.      |
| `deliveries_warehouse_idx`      | `deliveries (warehouse_id)`                            | Поиск поставок на склад и соединение с `warehouses`.  |
| `deliveries_delivered_at_idx`   | `deliveries (delivered_at)`                            | Фильтрация и сортировка поставок по времени.          |
| `warehouse_sections_parent_idx` | `warehouse_sections (warehouse_id, parent_section_id)` | Поиск дочерних секций одного склада.                  |




## Связи

Тернарное отношение имеет следующие проекции:

- `suppliers` 1:N `deliveries`;
- `products` 1:N `deliveries`;
- `warehouses` 1:N `deliveries`;
- `warehouses` 1:N `warehouse_sections`;
- `warehouse_sections` 1:N `warehouse_sections` — рекурсивная связь «родительская секция — дочерняя секция».

В совокупности они образуют отношение M:N:P между поставщиками, товарами и
складами. Его бизнес-уникальность обеспечивается ограничением
`deliveries_business_key_uq` с учётом номера партии.
