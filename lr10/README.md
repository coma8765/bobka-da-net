# Лабораторная работа № 10

Grafana 12.2.0 визуализирует существующую PostgreSQL `supply_lab` из `lr1`. Дашборд «Поставки: стоимость и качество» содержит шесть панелей: количество поставок, стоимость партий, долю отклонённых, график по дням, топ-10 складов и таблицу последних 100 поставок.

Проект решения: [RFC](docs/RFC.md). Выполнение и результаты проверок: [RFC-track.md](docs/RFC-track.md).

## Требования

- Podman с запущенной машиной и Compose provider (`podman compose version`).
- Существующий контейнер `lr1-postgres` с заполненной БД `supply_lab`.
- Python 3 для создания локальных паролей и проверки дашборда. Дополнительные Python-пакеты не нужны.
- Свободный локальный порт 3000.

Все команды ниже выполняются из корня репозитория `db`.

## Подготовка

Если машина Podman остановлена, выполнить `podman machine start`. Затем запустить существующую БД:

```bash
podman start lr1-postgres
podman exec lr1-postgres psql -X -U postgres -d supply_lab -c 'SELECT count(*), min(delivered_at), max(delivered_at) FROM public.deliveries;'
```

Если контейнера или базы ещё нет, сначала выполнить [лабораторную работу № 1](../lr1/README.md). Для её команд относительные пути `queries/...` предполагают, что в `/workspace` смонтирован каталог `lr1`: запускать создание такого контейнера из `lr1`. Уже заполненную БД заново не загружать.

Создать локальный `lr10/.env` со случайными паролями. Команда не перезаписывает существующий файл и не выводит секреты:

```bash
python3 - <<'PY'
from pathlib import Path
import secrets

p = Path('lr10/.env')
if not p.exists():
    with p.open('x') as f:
        f.write('GRAFANA_VERSION=12.2.0\n')
        f.write('GRAFANA_ADMIN_USER=admin\n')
        f.write('GRAFANA_ADMIN_PASSWORD=' + secrets.token_hex(24) + '\n')
        f.write('GRAFANA_DB_PASSWORD=' + secrets.token_hex(24) + '\n')
    p.chmod(0o600)
PY
```

Имена параметров также приведены в [.env.example](.env.example). Для совместимости с приведёнными shell-командами и проверочным скриптом использовать простые значения без кавычек и пробелов; сгенерированные шестнадцатеричные пароли подходят. Не добавлять `.env` в репозиторий.

Создать роль чтения. Повторный запуск обновляет пароль и настройки выделенной роли, не изменяя строки предметных таблиц:

```bash
set -a
source lr10/.env
set +a
podman exec -i --env GRAFANA_DB_PASSWORD lr1-postgres \
  psql -X -U postgres -d supply_lab \
  < lr10/queries/01_create_grafana_reader.sql
```

Роль получает только чтение четырёх таблиц, UTC и режим транзакций read-only по умолчанию. Пароль берётся `psql` из окружения, а не передаётся аргументом командной строки.

Создать общую сеть и подключить БД:

```bash
podman network exists supply-lab || podman network create supply-lab
podman inspect lr1-postgres --format '{{json .NetworkSettings.Networks}}'
```

Если в выведенных сетях ещё нет `supply-lab`, выполнить:

```bash
podman network connect supply-lab lr1-postgres
```

## Запуск

```bash
podman compose --env-file lr10/.env -f lr10/docker-compose.yaml config > /dev/null
podman compose --env-file lr10/.env -f lr10/docker-compose.yaml up -d
podman ps --filter name=lr10-grafana
```

Grafana доступна на [localhost:3000](http://localhost:3000). Логин — `admin`, пароль — значение `GRAFANA_ADMIN_PASSWORD` в локальном `.env`. Начальные учётные данные администратора применяются при первом создании volume; изменение переменной не меняет пароль уже существующего пользователя Grafana.

Открыть [дашборд поставок](http://localhost:3000/d/supply-overview). Источник `Supply Lab` и дашборд создаются автоматически через provisioning. В Connections → Data sources → Supply Lab нажать **Save & test**: ожидается `Database Connection OK`. Источник управляется файлом и недоступен для ручного редактирования; проверка соединения остаётся доступной.

Grafana подключается к `lr1-postgres:5432` внутри общей сети. Хостовый адрес `127.0.0.1:55432` для этого подключения не используется. Порт Grafana опубликован только на `127.0.0.1`.

## Работа с дашбордом

- Начальный период: 1 января 2025 — 5 сентября 2026, UTC; автообновление отключено.
- В фильтре «Склад» выбрать конкретный склад или «Все склады». Все панели используют одинаковые фильтры.
- Для записей после 4 сентября 2026 расширить диапазон времени, например до 1 октября 2026.
- Стоимость включает все статусы и выражена в условных денежных единицах. Это не выручка и не остатки товаров.
- Пустая выборка даёт нулевые количество и стоимость; вместо доли выводится «Нет поставок».
- Таблица ограничена последними 100 строками после применения фильтров. Топ-10 не включает стоимость остальных складов.
- График показывает отдельные серии по статусам. Дни без поставок не заполняются; разрывы длиннее суток не соединяются.

Исходный `timestamp without time zone` условно трактуется как UTC. Это соглашение учебного стенда, а не восстановленная временная зона склада.

## Автоматическая проверка

```bash
python3 lr10/scripts/verify.py
```

Проверка получает запросы из уже загруженного дашборда, исполняет их через API Grafana и сравнивает с независимой агрегацией исходных строк PostgreSQL. Проверяются все шесть панелей, фильтр склада, короткий и пустой периоды, текущие данные, справочные названия и переменная со всеми складами. Скрипт использует пароли из локального `.env`, ничего не изменяет и не выводит пароли.

Контрольные значения исходного периода:

| Показатель | Значение |
| --- | ---: |
| Поставки | 5000 |
| Стоимость партий | 280292140666.85 |
| Принято / на проверке / отклонено | 3019 / 1008 / 973 |
| Доля отклонённых | 19.46% |

На момент реализации живая БД содержит ещё шесть более поздних поставок. При диапазоне до 1 октября 2026 итог — 5006 поставок и `280292149841.85`. Скрипт сверяется с текущей БД, поэтому допускает последующие изменения учебных данных.

Для проверки восстановления:

```bash
podman compose --env-file lr10/.env -f lr10/docker-compose.yaml restart
```

После готовности контейнера повторить `python3 lr10/scripts/verify.py`.

## Изменения и остановка

Все SQL панелей хранятся только в [JSON дашборда](grafana/dashboards/supply-overview.json). После правки JSON Grafana перечитывает его автоматически; изменения provisioning источника требуют перезапуска. Сохранение изменений дашборда через интерфейс отключено, чтобы файлы оставались источником конфигурации.

```bash
podman compose --env-file lr10/.env -f lr10/docker-compose.yaml down
```

Команда останавливает Grafana и удаляет её контейнер. Именованный volume сохраняется; существующая PostgreSQL и внешняя сеть остаются доступны.
