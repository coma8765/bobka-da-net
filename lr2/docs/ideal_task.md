  1. SELECT с предикатом сравнения — найти строки по обычным условиям сравнения (=, <>, <, >). В примере нужно найти аргентинских
     клиентов из городов, где есть несколько клиентов.

  2. SELECT с BETWEEN — выбрать записи, значение которых попадает в заданный диапазон. Пример: заказы за определённый период.
  3. SELECT с LIKE — выполнить поиск по части текстового значения. Пример: найти категории, в описании которых встречается слово pasta.
  4. SELECT с IN и подзапросом — сначала подзапросом получить множество идентификаторов, затем отфильтровать по нему основной запрос.
     Пример: заказы лондонских клиентов, оформленные конкретным сотрудником.

  5. SELECT с EXISTS и подзапросом — проверить существование связанных записей. Идейно: найти товары, которые ни разу не участвовали в
     заказах. В приведённом SQL корреляция выражена некорректно, поэтому при реализации логику стоит уточнить через коррелированный NOT
     EXISTS.

  6. SELECT со сравнением и квантором ALL — сравнить значение с каждым значением, возвращённым подзапросом. Пример: найти товары дороже
     всех товаров выбранной категории.

  7. Агрегатные функции в выражениях столбцов — использовать AVG, SUM, COUNT и арифметические выражения над агрегатами. Пример:
     вычислить среднюю стоимость заказа двумя способами и сравнить результаты.

  8. Скалярные подзапросы в столбцах — для каждой строки основного результата отдельными подзапросами вычислить агрегированные
     показатели. Пример: вывести товар и статистику его цены в заказах. В документе результат MIN ошибочно назван MaxPrice.

  9. Простое выражение CASE — сравнивать одно выражение с несколькими конкретными значениями. Пример: классифицировать заказы как
     сделанные в этом году, прошлом году или несколько лет назад.

  10. Поисковое выражение CASE — последовательно проверять независимые логические условия. Пример: разделить товары на ценовые
     категории.

  11. Создание временной таблицы через SELECT INTO — агрегировать исходные данные и поместить результат в локальную временную таблицу.
     Пример: сохранить количество продаж и выручку по каждому товару.

  12. Подзапросы как производные таблицы в FROM — сформировать временные агрегированные наборы и соединить их с основной таблицей.
     Пример: определить самый продаваемый товар по количеству и по выручке, объединив результаты через UNION.

  13. Подзапрос с глубиной вложенности 3 — построить несколько последовательно вложенных уровней вычислений. Пример: сначала посчитать
     продажи по товарам, затем максимальное количество продаж, после чего получить название лидирующего товара.

  14. GROUP BY без HAVING — сгруппировать строки и рассчитать агрегаты для каждой группы. Пример: для товаров первой категории вывести
     основную, среднюю и минимальную цену.

  15. GROUP BY с HAVING — после группировки отфильтровать группы по агрегированному условию. Пример: найти категории, средняя цена
     товаров в которых выше средней цены по всем товарам.

  16. Однострочный INSERT — добавить в таблицу одну новую запись, используя конкретные значения, NULL и значения по умолчанию.

  17. Многострочный INSERT ... SELECT — вставить строки, полученные другим запросом. Пример: добавить товар в последний заказ заданного
     клиента, получив идентификатор заказа скалярным подзапросом.

  18. Простой UPDATE — изменить значение столбца у выбранных строк. Пример: увеличить цену конкретного товара в 1,5 раза.
  19. UPDATE со скалярным подзапросом в SET — вычислить новое значение отдельным запросом. Пример: заменить цену товара его средней
     ценой из истории заказов.

  20. Простой DELETE — удалить записи по обычному условию. Пример: удалить заказы без указанного клиента.

  21. DELETE с подзапросом в WHERE — подзапросом определить множество удаляемых строк. Пример: удалить товары выбранной подкатегории,
     которые не встречались в заказах. В документе пример рассчитан на AdventureWorks, поэтому его нужно адаптировать к используемой БД.

  22. Простое CTE (WITH) — вынести промежуточную агрегацию в именованный табличный набор и использовать его в основном запросе. Пример:
     посчитать число поставок каждого поставщика, а затем среднее число поставок. Пример дан для БД SPJ и также требует адаптации.

  23. Рекурсивное CTE — создать иерархию, состоящую из начальной и рекурсивной частей. Пример: пройти дерево подчинённости сотрудников
     от руководителя к подчинённым и вывести уровень каждого сотрудника.

  24. Оконные MIN, MAX, AVG ... OVER() — рассчитывать агрегаты внутри группы, не сворачивая исходные строки. Пример: для каждой строки
     заказа показать цену товара и минимальную, максимальную и среднюю цену этого товара.

  25. Удаление дублей через ROW_NUMBER() — самостоятельно придумать запрос, который порождает полностью одинаковые строки, пронумеровать
     их внутри групп дублей и оставить только одну строку из каждой группы.

  В документе есть несколько синтаксических опечаток и логических неточностей, поэтому эти запросы лучше воспринимать как требования к используемым конструкциям SQL, а не как эталонный код для буквального копирования.
